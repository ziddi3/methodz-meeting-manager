Coverage, remediation, and rerun planning are not production approval

  • The matrix checks six documented rows: Desktop Chromium, Desktop non-Chromium, Android Chrome, iOS Safari, Tablet, and Two-device.
  • Only evidence with complete environment metadata and the established metadata-only privacy contract is accepted.
  • Different commit SHAs remain separate. A mixed evidence set cannot produce a cross-commit completeness claim.
  • Blocking GitHub issue numbers are carried only as bounded numeric references from accepted evidence.
  • Remediation drafts are operator aids. They do not prove that a software defect exists and they are never submitted automatically.
  • A code change creates a new evidence boundary. Ready rows from the old commit must be revalidated before the new commit can claim complete physical-device coverage.
  • Environment-only and evidence-only reruns stay on the same commit only while code remains unchanged.
  • Rehearsal handoff fragments carry only row and commit-policy metadata. They never carry meeting data, credentials, provider state, or arbitrary notes.
  • No meeting records, browser-local business values, provider state, queues, transfer packages, credentials, or private keys are read or written.
  • Coverage completeness does not prove production readiness, device identity, authorization, delivery, legal approval, or regulatory compliance.
