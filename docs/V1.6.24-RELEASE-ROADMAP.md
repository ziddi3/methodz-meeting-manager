# Methodz Meeting Manager v1.6.24 Release Roadmap

## Release intent

Advance the evidence-driven 1.x roadmap by turning one exact-commit coverage matrix and its current remediation worklist into a deterministic physical-device rerun plan.

This release does not invent a new production subsystem. It codifies the v1.6.23 next-target rules that evidence must stay attached to the commit it tested, that code remediation creates a new evidence boundary, and that environment-only or evidence-only work may stay on the same commit only when code did not change.

## Definition of done

- [x] rerun logic is isolated in a portable side-effect-free core;
- [x] coverage and remediation inputs must both be version `1.0.0`;
- [x] coverage and remediation commit SHAs must match exactly;
- [x] all six documented coverage rows remain the bounded universe;
- [x] remediation state and action type mismatches fail closed;
- [x] any code-remediation row creates a `new-commit-cycle`;
- [x] a new-commit cycle revalidates all six physical-device rows because old-commit evidence cannot establish changed-code coverage;
- [x] blocked, incomplete, and missing rows remain same-commit work when no code remediation exists;
- [x] ready rows are excluded from same-commit reruns;
- [x] building a plan requires explicit operator action;
- [x] coverage or remediation changes invalidate the plan;
- [x] JSON summary and Markdown rehearsal-checklist downloads are explicit and metadata-only;
- [x] the static application makes no provider or GitHub API call and schedules no background work;
- [x] browser storage, meeting records, queues, and transfer contents are not read or written by rerun planning;
- [x] portable and Chromium tests cover exact-commit validation, code-change expansion, same-commit planning, invalidation, downloads, storage non-use, and mobile containment;
- [x] app shell remains `1.6.12`;
- [x] meeting-record schema remains `1.6.0`;
- [x] browser-local storage remains the default meeting-record provider;
- [x] no hosted production provider or deployment over `hub.methodz.ca` is introduced.

## Next 1.x targets

1. collect real physical-device evidence for the current application commit;
2. when a field row fails, use the remediation draft to isolate the smallest code cause before changing the commit;
3. after a code fix, use the rerun plan as the reminder that all six rows need evidence on the resulting commit before that commit can claim complete coverage;
4. after environment-only or evidence-only work, rerun only the unresolved rows on the same commit while code remains unchanged;
5. compare Workspace Capacity timing evidence in the same environment when field friction is performance-related;
6. improve Meeting-Day, Preparation, Follow-Up Planning, Decision Register, or Outcomes only where real field evidence identifies operator friction;
7. keep Calendar, CRM, authentication, AI summary automation, and production-provider work inside the explicit 2.0 approval boundary;
8. preserve browser-local storage as the default until a hosted provider satisfies the production evidence gate.
