# Methodz Meeting Manager v1.6.27 Release Roadmap

## Release intent

Advance the evidence-driven 1.x roadmap by binding the existing Field Rehearsal return context to the exact metadata-only JSON bytes produced by the explicit download action.

This release is an integrity hardening step, not a new production subsystem. It keeps the browser file-selection boundary intact, keeps coverage evaluation explicit, and does not turn a SHA-256 receipt into a device, person, authorization, or production-readiness claim.

## Definition of done

- [x] a portable side-effect-free `field-evidence-integrity-core.js` hashes exact generated text with SHA-256;
- [x] a receipt is generated only as part of the explicit **Download Metadata Evidence** action;
- [x] the Field Rehearsal return contract advances to `1.1.0` and requires a valid 64-character lowercase SHA-256 receipt;
- [x] return metadata remains bounded to contract version, coverage row, exact commit SHA, readiness, and receipt;
- [x] report contents, file path, file name, meeting data, credentials, provider state, queues, and arbitrary notes do not cross the handoff;
- [x] `evidence.html` still requires explicit local file selection and **Load Selected Evidence**;
- [x] when return context is active, selected file bytes are hashed and at least one file must match the returned receipt before return-driven evidence is accepted;
- [x] the receipt-matched report must also retain the returned coverage row, exact commit, and readiness after existing evidence normalization;
- [x] receipt mismatch, invalid evidence, row drift, commit drift, or readiness drift fails visibly with no return-driven report accepted;
- [x] ordinary manual evidence import remains available when the Coverage Matrix is opened without return context;
- [x] accepted evidence remains in memory only and coverage evaluation remains a separate explicit operator action;
- [x] no browser storage, meeting-record mutation, provider, GitHub API, synchronization, transfer mutation, automatic import, issue creation, or background automation is introduced;
- [x] portable tests cover the SHA-256 helper, exact-byte behavior, receipt validation, return-fragment validation, and metadata drift;
- [x] Chromium coverage exercises exact downloaded bytes, post-download tampering, launch drift, malformed return metadata, storage non-use, and narrow-phone containment;
- [x] the integrity helper is pre-cached only as an ordinary static app-shell asset;
- [x] application shell remains `1.6.12`;
- [x] meeting-record schema remains `1.6.0`;
- [x] browser-local storage remains the default meeting-record provider;
- [x] no hosted production provider or deployment over `hub.methodz.ca` is introduced.

## Evidence meaning

A successful receipt check establishes only that the local JSON selected for import has exactly the same bytes as the metadata-only payload hashed during the explicit Field Rehearsal download action.

It does not authenticate the operator, attest the physical device, validate external screenshots or traces, prove delivery, prove authorization, prove legal or regulatory status, or establish production readiness.

## Next 1.x targets

1. use the exact-file receipt handoff during real Android, iOS, tablet, desktop Chromium, desktop non-Chromium, and two-device rehearsals for the current target commit;
2. explicitly import each downloaded report, verify the receipt, and evaluate the expected row under the exact commit actually tested;
3. when a row fails, keep remediation limited to the smallest evidence-supported code cause;
4. after code remediation, enter the actual resulting commit SHA and rerun all six rows because the evidence boundary changed;
5. after environment-only or evidence-only work, rerun only unresolved rows while the code commit remains unchanged;
6. compare Workspace Capacity timing evidence when field friction is performance-related;
7. improve Meeting-Day, Preparation, Follow-Up Planning, Decision Register, or Outcomes only when real field evidence identifies operator friction;
8. keep Calendar, CRM, authentication, AI summary automation, and production-provider work inside the explicit 2.0 approval boundary;
9. preserve browser-local meeting storage as the default until a hosted provider satisfies the production evidence gate.
