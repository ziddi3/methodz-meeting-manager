# Methodz Meeting Manager v1.6.22 Release Roadmap

## Release intent

Advance the evidence-driven 1.x roadmap by converting individual Field Rehearsal reports into a deterministic same-commit coverage matrix.

This release does not add production infrastructure or claim production readiness. It makes physical-device evidence gaps visible so later work can be driven by concrete failed, blocked, incomplete, or missing rehearsal rows.

## Definition of done

- [x] `evidence.html` is reachable from Workspace Home.
- [x] only explicit file loading reads selected JSON evidence.
- [x] portable coverage core accepts only `methodz-field-rehearsal-evidence` version `1.0.0` reports.
- [x] source privacy-boundary violations and incomplete environment metadata fail closed.
- [x] unknown properties are ignored instead of copied forward.
- [x] imported evidence is bounded to 50 reports and remains in memory only.
- [x] evidence is grouped by exact commit SHA and mixed commits cannot silently satisfy one matrix.
- [x] six documented coverage rows are evaluated deterministically.
- [x] repeated same-row evidence uses the latest report as current state while preserving evidence counts.
- [x] blocking GitHub issue numbers are retained only as bounded numeric references.
- [x] coverage-summary download is explicit and metadata-only.
- [x] browser storage, provider state, meeting records, queues, and transfer contents are not read or written.
- [x] service worker caches only the new static application assets.
- [x] portable and Chromium tests cover validation, same-commit isolation, coverage math, privacy, explicit actions, clearing, and mobile containment.
- [x] app shell remains `1.6.12`.
- [x] meeting-record schema remains `1.6.0`.
- [x] browser-local storage remains the default meeting-record provider.
- [x] no hosted production provider or silent automation is introduced.

## Evidence collection target

Collect and evaluate the same application commit across:

1. Desktop Chromium: Chrome or Edge;
2. Desktop non-Chromium: Firefox or Safari;
3. Android Chrome;
4. iOS Safari;
5. tablet browser;
6. two-device transfer/acceptance rehearsal.

A row may be rerun on the same commit after environment or test setup corrections. Code fixes produce a new commit and therefore a new coverage matrix.

## Next 1.x targets

1. collect real physical-device reports and use missing/fail/blocked/incomplete rows to create narrowly scoped remediation issues;
2. after each remediation, rerun the affected row on the new commit rather than carrying an old pass forward;
3. compare Workspace Capacity timing evidence for the same environments when performance friction is reported;
4. improve Meeting-Day, Preparation, Follow-Up Planning, Decision Register, and Outcomes only where field evidence identifies specific operator friction;
5. keep Calendar, CRM, authentication, AI summary automation, and production-provider work inside the explicit 2.0 approval boundary;
6. preserve browser-local storage as the default until a hosted provider satisfies the production evidence gate.
