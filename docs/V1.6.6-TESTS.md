# Methodz Meeting Manager v1.6.6 Test Plan

## Automated Node contract

Run:

```bash
node tests/v166-sync-portability.mjs
```

The contract verifies:

- queue package creation and canonical integrity verification;
- preservation of unknown fields and attachment references;
- fail-closed tamper rejection;
- unsupported package-version rejection;
- tenant mismatch rejection;
- private JWK and private-key rejection;
- credential and access-token rejection;
- embedded-binary rejection;
- keep-local queue merge;
- newest-metadata queue merge;
- retain-both queue merge with regenerated identifiers;
- protected-state compaction rules;
- removal of explicitly approved completed entries only;
- bounded metadata-only operator event retention;
- operator evidence integrity verification;
- evidence tamper rejection;
- meeting-content leakage rejection;
- tenant queue recognition by workspace backup inspection and restore planning.

## Automated browser regression

Run from a static server:

```bash
npx playwright test tests/v166-sync-portability.spec.js --reporter=line
```

The browser suite verifies:

- a queue package is previewed before mutation;
- the queue remains unchanged until approval;
- imported entries remain pending and are not automatically processed;
- the disposable remote remains unchanged after import;
- tenant switching isolates queue storage;
- returning to a tenant restores its queue;
- reload recovers queued work;
- response loss produces retryable work;
- retry reuses the original idempotency key;
- successful replay returns and persists the provider conflict token;
- archived remote pulls create an Archive Vault envelope with `originalRecordId` and `archivedAt`.

## Manual release checklist

### Queue export

1. Save at least one meeting record.
2. Enqueue a push without processing it.
3. Expand **Queue portability, compaction, and operator evidence**.
4. Export the queue package.
5. Confirm the file contains `methodz-sync-rehearsal-queue`, package version `1.0.0`, and integrity metadata.
6. Confirm no operation was processed by exporting the package.

### Import preview and approval

1. Switch to another empty rehearsal tenant.
2. Choose a queue package from the first tenant.
3. Confirm the import is rejected because the active tenant does not match.
4. Return to the original tenant.
5. Choose the package again.
6. Confirm the preview displays entry, operation, conflict, protected-work, tenant-reference, and timestamp information.
7. Confirm the local queue remains unchanged before approval.
8. Choose each merge strategy in a disposable browser profile and review the result.
9. Confirm imported entries remain unprocessed after approval.

### Tamper rejection

1. Copy a valid queue package.
2. Change an entry state or timestamp without recalculating integrity.
3. Import the modified file.
4. Confirm the package is rejected.
5. Confirm the existing local queue is unchanged.

### Unsafe material rejection

Using a disposable copy of a package, add one of the following and recalculate the package body only for diagnostic testing:

- a private JWK `d` parameter;
- a `privateKey` or `privateJwk` field;
- an `accessToken`, `apiKey`, or password field;
- an embedded `data:` URL;
- a recognized binary field such as `fileBytes` or `contentBase64`.

Confirm every package fails closed before queue mutation.

### Compaction protection

1. Create pending, offline, retryable-error, blocked-conflict, and completed entries.
2. Run **Review Stale Completed Entries**.
3. Confirm only completed candidates appear.
4. Select and remove a completed candidate.
5. Confirm all protected work remains.
6. Confirm meeting records and remote records remain unchanged.

### Operator evidence

1. Enqueue, process, retry, preview, switch connectivity, resolve a conflict, import, export, and compact in a disposable profile.
2. Export operator evidence.
3. Confirm it contains opaque references, operation metadata, counts, and timestamps.
4. Confirm it does not contain meeting titles, notes, summaries, attendees, signatures, record IDs, tenant IDs, idempotency keys, conflict tokens, credentials, or private-key material.
5. Modify an event result and confirm the inspector rejects the tampered package in the Node test.

### Workspace recovery

1. Create queues under two rehearsal tenants.
2. Export a complete workspace backup.
3. Inspect it through **Recovery Readiness**.
4. Confirm both tenant-scoped queue keys are recognized.
5. Run the current workspace drill and confirm checksum verification passes.
6. Restore only in a disposable browser profile.
7. Confirm each tenant queue is recovered independently.

### Service-worker boundary

1. Inspect `service-worker.js`.
2. Confirm the v1.6.6 assets are cached.
3. Confirm there is no `sync` event listener.
4. Close the application with pending queue work.
5. Wait and reopen it.
6. Confirm the pending entry remains pending rather than being processed in the background.

## Release gate

Do not merge until:

- JavaScript syntax checks pass;
- the v1.6.5 rehearsal contract remains green;
- the v1.6.6 portability contract passes;
- the v1.6.6 Chromium browser suite passes;
- existing static, recovery, custody, cryptographic, provider, and browser workflows remain green;
- direct-file and ordinary static-host deployment remain intact;
- no production endpoint or credential has been introduced;
- the record schema remains `1.6.0`.
