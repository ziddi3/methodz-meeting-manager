# Methodz Meeting Manager v1.6.9 Transfer Acceptance

## Product boundary

Methodz Meeting Manager remains a task-focused meeting preparation, capture, analysis, archive, and records tool. This release does not reclassify it as Method Hub, Nexus Hub, a storefront, a business container, the Cathedral, or a Cathedral wing. It must not deploy over `hub.methodz.ca`.

## Purpose

Version 1.6.9 turns the completed v1.6.8 transfer mechanism into an operator acceptance workflow. The destination browser can verify the transferred workspace, record explicit browser-local acceptance, preview a rollback, restore the pre-import destination snapshot, and measure aggregate workspace health.

## Guided destination acceptance

The acceptance panel checks:

- active meeting records;
- Archive Vault records;
- revision groups;
- attendee and organization directories;
- meeting templates;
- governance, retention, release, approval, redaction, and policy metadata;
- public verification keys;
- custody records;
- recovery and drill logs;
- tenant synchronization queue state;
- the latest verified v1.6.8 destination-import report;
- the integrity of the pre-import recovery package.

Where the v1.6.8 report contains expected counts, v1.6.9 compares them with the current destination workspace. Mismatches fail closed. Optional categories that are empty remain visible as review items instead of being silently treated as complete.

Acceptance requires:

1. successful automated checks;
2. explicit review of every category;
3. confirmation that the pre-import recovery package will be retained;
4. the typed phrase `ACCEPT`.

Acceptance evidence is browser-local workflow metadata. It does not authenticate a person or device and does not prove delivery, authority, legal approval, or identity.

## Rollback rehearsal

The rollback path uses the complete pre-import recovery package created by v1.6.8.

1. Preview the replacement plan without writing.
2. Review add, replace, unchanged, remove, and ignored counts.
3. Confirm understanding of the replacement operation.
4. Type `ROLLBACK`.
5. Approve the final browser confirmation.
6. Preserve the current transferred workspace as a pre-rollback recovery package.
7. Restore the pre-import snapshot.
8. Verify every written and removed entry.
9. Record metadata-only success or failure evidence.

If the rollback write fails, the application attempts to restore and verify the current transferred snapshot. Both packages remain explicit recovery tools, not silent background behavior.

## Meeting-Day Mode

Meeting-Day Mode prioritizes the direct meeting workflow:

- meeting information;
- organizations and representatives;
- attendance;
- agenda;
- discussion notes;
- decisions;
- follow-up tasks;
- summary;
- save and end-of-meeting controls.

Governance, recovery, provider, synchronization, transfer, archive, and diagnostics panels remain available through **Show Supporting Panels**. Section navigation is horizontally scrollable on phones and tablets. The mode and last active section are restored from browser-local preferences.

Keyboard shortcut: `Alt+M` toggles Meeting-Day Mode.

## Large-workspace diagnostics

Diagnostics report only aggregate metadata:

- recognized entry count;
- total measured bytes;
- largest-entry byte count without its key name;
- JSON parse-error count;
- active, archived, and revision counts;
- size buckets;
- scan duration;
- browser storage usage and quota ratio when available.

Reports exclude meeting content, raw record IDs, attendee names, signatures, credentials, private keys, and storage-key names.

## Deployment

The release remains:

- static HTML, CSS, and JavaScript;
- directly usable from `meeting.html` for core workflows;
- deployable to an ordinary static host;
- free of runtime package dependencies and build commands;
- browser-local by default;
- explicit and user-controlled for transfer, acceptance, rollback, and synchronization.

The app-shell version advances to `1.6.9`. The meeting-record schema remains `1.6.0`.
