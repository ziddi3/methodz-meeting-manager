# Methodz Meeting Manager v1.6.10 Test Plan

## Portable registry test

Run:

```bash
node tests/v1610-panel-registry.mjs
```

Coverage:

- valid definitions register;
- duplicate IDs fail;
- invalid groups fail;
- stable selectors bind metadata to the document;
- required capture omissions fail;
- missing insertion anchors fail;
- reversed Meeting-Day DOM order fails with `PANEL_ORDER_MISMATCH`;
- Meeting-Day panel resolution follows priority rather than headings;
- diagnostics remain metadata-only.

## Browser registry test

Run:

```bash
npx playwright test tests/v1610-panel-registry.spec.js --reporter=line
```

Coverage:

- the complete current shell validates;
- all nine capture panels are registered;
- renaming visible headings does not break navigation;
- navigation focuses the first usable control;
- removing a required panel creates a visible blocking diagnostic;
- a registry failure never collapses saved records or governance controls;
- archive, recovery, synchronization, Device Readiness, transfer, and acceptance panels retain stable registry groups;
- diagnostics exclude business values;
- the 390-pixel layout has no page-level horizontal overflow.

## Static validation

CI must verify:

- app shell `1.6.10` and record schema `1.6.0`;
- v1.6.10 files exist and load in the required order;
- archive loads configuration but not interactive registry modules;
- service worker caches the registry shell;
- service worker has no sync, transfer, acceptance, rollback, registry-data, or workspace-data handler;
- deployment assets do not reference `hub.methodz.ca`;
- field evidence JSON parses and declares the current versions;
- all earlier cryptographic, recovery, custody, provider, synchronization, transfer, and acceptance core tests remain green.

## Manual shell failure tests

Use a disposable branch or browser dev tools.

1. Remove one required capture panel and rerun validation.
2. Confirm Panel Registry Diagnostics becomes visible.
3. Enter Meeting-Day Mode.
4. Confirm the remaining meeting controls and supporting panels stay visible.
5. Restore the panel.
6. Reverse two core capture panels in the DOM.
7. Confirm `PANEL_ORDER_MISMATCH` blocks collapse.
8. Restore the order and confirm diagnostics return to valid.
9. Rename every capture heading and confirm registry navigation still works.

## Print test

- Print a record from `archive.html`.
- Confirm registry, Meeting-Day, synchronization, provider, transfer, acceptance, and diagnostic controls are absent.
- Confirm meeting information, attendance, agenda, decisions, tasks, attachments, summary, and audit information remain legible.

## Physical-device field rehearsal

Complete `docs/V1.6.10-FIELD-REHEARSAL.md` on:

- Android phone;
- iPhone;
- tablet;
- desktop Chromium and one additional browser family.

Create one metadata-only evidence file per tested profile using `docs/field-rehearsal-evidence-template.json`.

## Release blockers

Do not merge or mark field-ready if:

- a duplicate registry ID is accepted;
- a required capture panel is missing without a visible failure;
- Meeting-Day order drift is only a warning;
- a registry failure hides meeting or recovery controls;
- Meeting-Day navigation depends on current heading text;
- diagnostics contain meeting values or storage values;
- direct-file core operation fails;
- service worker processes business data;
- any existing provider, recovery, signing, synchronization, transfer, acceptance, rollback, mobile, or browser suite fails;
- the app shell differs from `1.6.10` or the record schema differs from `1.6.0`.
