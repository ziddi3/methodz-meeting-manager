# Methodz Meeting Manager v1.6.5 Test Plan

## Automated contract tests

Run:

```bash
node tests/v165-sync-rehearsal.mjs
```

The suite verifies:

- offline enqueue without a provider request;
- queue recovery through a new coordinator instance;
- reconnect and explicit push processing;
- unknown-field, attachment-reference, governance, and signature-metadata preservation;
- response loss after commit;
- deterministic retry using the original idempotency key;
- idempotent replay rather than duplicate delivery;
- local mutation after enqueue blocking;
- remote conflict-token blocking;
- three-way changed-path preview without values;
- explicit rebase-and-push preparation;
- read-only remote pull preview;
- explicit queued pull and local application;
- tenant isolation;
- metadata-only report redaction;
- fail-closed private-JWK rejection.

## Browser checklist

1. Open `meeting.html` directly and from a local static server.
2. Confirm the Synchronization Rehearsal Coordinator appears before Saved Meeting Records.
3. Save a meeting record.
4. Select it in the rehearsal panel and enqueue a push.
5. Confirm the queue changes but the disposable remote is not written until Process is pressed.
6. Process the entry and confirm it completes.
7. Preview remote changes and confirm previewing does not alter Saved Meeting Records.
8. Enqueue and process a pull candidate.
9. Toggle offline mode and confirm new and pending entries show `offline`.
10. Reconnect and confirm entries return to `pending` without processing automatically.
11. Change a local record after enqueue and confirm the entry becomes `blocked-conflict`.
12. Review changed paths and choose Keep Local, Accept Remote, or Rebase & Push.
13. Reload the page and confirm non-cleared queue entries remain.
14. Export a rehearsal report and inspect the JSON.
15. Confirm no meeting title, notes, summary, attendee, signature, raw record ID, raw idempotency key, raw conflict token, or credential appears.
16. Reset the disposable remote and confirm local meeting records remain.
17. Confirm the rehearsal workspace is hidden from print output.
18. Confirm the service worker caches v1.6.5 assets on HTTPS or localhost.

## Release gate

The release is ready only when:

- Offline Synchronization Rehearsal passes;
- Hosted Provider Pilot passes;
- Hosted Provider Conformance passes;
- Static and Browser Checks passes;
- the existing cryptographic, recovery, custody, archive, retention, approval, receipt, and disposition regressions remain green;
- no production endpoint or credential is present;
- the record schema remains `1.6.0`;
- all queue processing remains explicit and user-controlled.
