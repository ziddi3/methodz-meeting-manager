# Methodz Meeting Manager v1.6.9 Test Plan

## Automated core checks

Run:

```bash
node tests/v169-transfer-acceptance.mjs
```

The test verifies:

- matching transfer counts produce a ready acceptance report;
- count mismatches fail closed;
- pre-import recovery requires a valid checksum;
- acceptance reports exclude record IDs, attendee names, and storage-key names;
- rollback planning exposes only aggregate counts;
- rollback evidence remains metadata-only;
- workspace diagnostics expose aggregate size and timing only.

## Browser checks

Run:

```bash
npx playwright test tests/v169-transfer-acceptance.spec.js --reporter=line
```

Coverage:

- Transfer Acceptance panel loads after the v1.6.8 transfer workspace.
- A disposable verified destination report and pre-import package pass automated checks.
- Explicit category review plus typed `ACCEPT` records browser-local acceptance.
- Acceptance evidence excludes raw record IDs, attendee names, and storage-key names.
- Rollback preview performs no write.
- Meeting-Day Mode hides supporting panels while preserving an explicit expansion control.
- Meeting-Day preference survives reload.
- Aggregate diagnostics remain metadata-only.
- A 390-pixel phone viewport has no page-level horizontal overflow.
- A two-browser-profile scenario transfers disposable data, accepts the destination, restores the pre-import snapshot, and preserves a current-state recovery package.

## Manual two-profile rehearsal

Use two separate browser profiles or two different supported browsers. Use disposable meeting data only.

### Source profile

1. Create one active disposable meeting.
2. Archive one disposable meeting.
3. Add one revision, one attendee-directory entry, one organization-directory entry, one template, and one queued rehearsal item.
4. Save all work.
5. Run Device Readiness.
6. Build and download the v1.6.8 transfer bundle.
7. Keep the source profile unchanged.

### Destination profile

1. Create a small disposable destination workspace.
2. Run Device Readiness.
3. Import and inspect the transfer bundle.
4. Run the v1.6.8 no-write recovery drill.
5. Complete all transfer confirmations and type `TRANSFER`.
6. Apply and reload.
7. Run **Post-Transfer Acceptance**.
8. Review all categories, retain the recovery package, type `ACCEPT`, and record acceptance.
9. Export the metadata-only acceptance report.
10. Run **Preview Rollback** and record the add, replace, unchanged, remove, and ignored counts.
11. Download a fresh destination backup.
12. Confirm rollback understanding, type `ROLLBACK`, and apply.
13. Reload and verify that the original destination disposable workspace is restored.
14. Download the pre-rollback recovery package and confirm it contains the transferred disposable state.
15. Export rollback evidence and verify that it contains no meeting text, attendee names, signatures, raw record IDs, or storage-key names.

## Meeting-Day Mode manual checks

At desktop, tablet, and narrow phone widths:

- enter and exit Meeting-Day Mode;
- navigate through every direct meeting section;
- add attendees and tasks;
- type long discussion notes and decisions;
- save and reopen a meeting;
- expand and collapse supporting panels;
- reload and confirm mode and last-section restoration;
- use `Alt+M` with keyboard navigation;
- confirm focus remains visible;
- confirm no horizontal page overflow.

## Rollback failure injection

In a disposable browser profile only:

1. Preview rollback successfully.
2. Temporarily monkey-patch `localStorage.setItem` to fail for one recognized workspace key.
3. Apply rollback.
4. Confirm the operation reports failure.
5. Confirm the current transferred snapshot is restored and verified.
6. Confirm a metadata-only failure report is retained.
