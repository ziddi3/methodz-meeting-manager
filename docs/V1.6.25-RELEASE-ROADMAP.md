# Methodz Meeting Manager v1.6.25 Release Roadmap

## Release intent

Advance the evidence-driven 1.x roadmap by making the existing exact-commit rerun plan directly usable at the Field Rehearsal surface.

This release does not add a production subsystem. It reduces operator friction in the next documented target: collecting real physical-device evidence for the commit that is actually under test.

## Definition of done

- [x] Field Rehearsal launch logic is isolated in a portable side-effect-free core;
- [x] only the six documented coverage rows are recognized;
- [x] only bounded row/commit-policy metadata may cross the handoff;
- [x] same-commit launch targets are pinned to the exact source commit;
- [x] new-commit launches require an explicit valid resulting commit SHA different from the source commit;
- [x] rerun-row launch remains an explicit operator action;
- [x] recognized launch fragments are validated and removed from the address bar;
- [x] malformed or tampered handoffs fail visibly without populating the rehearsal commit;
- [x] deterministic row hints may prefill platform/browser fields, while OS/browser versions remain operator-entered;
- [x] actual environment inspection remains explicit and may replace the hinted viewport with the measured viewport;
- [x] no meeting record or browser-local business value is read or written by the launch layer;
- [x] no provider, GitHub API, synchronization, transfer, issue creation, test execution, or background automation is introduced;
- [x] portable and Chromium tests cover commit-boundary enforcement, fragment validation, navigation, storage non-use, and mobile containment;
- [x] app shell remains `1.6.12`;
- [x] meeting-record schema remains `1.6.0`;
- [x] browser-local storage remains the default meeting-record provider;
- [x] no hosted production provider or deployment over `hub.methodz.ca` is introduced.

## Next 1.x targets

1. use the handoff on real Android, iOS, tablet, desktop Chromium, desktop non-Chromium, and two-device rehearsals for the current target commit;
2. feed downloaded metadata-only Field Rehearsal reports back into the exact-commit Coverage Matrix;
3. when a row fails, keep remediation limited to the smallest evidence-supported code cause;
4. after code remediation, enter the actual resulting commit SHA and rerun all six rows because the evidence boundary changed;
5. after environment-only or evidence-only work, rerun only unresolved rows while the code commit remains unchanged;
6. compare Workspace Capacity timing evidence when field friction is performance-related;
7. improve Meeting-Day, Preparation, Follow-Up Planning, Decision Register, or Outcomes only when real field evidence identifies operator friction;
8. keep Calendar, CRM, authentication, AI summary automation, and production-provider work inside the explicit 2.0 approval boundary;
9. preserve browser-local meeting storage as the default until a hosted provider satisfies the production evidence gate.
