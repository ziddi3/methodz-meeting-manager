# v1.6.19 Workspace Home Release Roadmap

## Release intent

Improve static deployability and lifecycle ergonomics by giving Methodz Meeting Manager a true repository-root entry point and an optional aggregate-only workspace snapshot, while preserving operator authority, schema stability, and browser-local default operation.

## Completed scope

- Static `index.html` Workspace Home.
- Direct lifecycle routing to Preparation, Meeting-Day capture, Decision Register, and Meeting Outcomes.
- Supporting routes to Archive Vault, Device Readiness, and package verification.
- Portable aggregate-only Workspace Home core.
- Explicit snapshot refresh with no automatic record read on page load.
- Aggregate active, completed, archived, upcoming, unscheduled, overdue, unassigned, and needs-scheduling signals.
- Bounded record and task scanning with visible partial-coverage state.
- Stable PWA identity with repository-root start route.
- Static service-worker cache wiring for home assets.
- Portable, Chromium, mobile, privacy, architecture, changelog, and release documentation.

## Release gates

- All existing pull-request workflows remain green.
- Dedicated portable and Chromium Workspace Home jobs pass.
- `index.html` works through an ordinary static server.
- No meeting-record migration is introduced.
- No record read occurs before explicit snapshot refresh.
- No record mutation, automatic assignment, reminder, notification, provider write, or synchronization path is introduced.
- Aggregate output retains no meeting identity, attendee identity, meeting prose, task prose, Assigned To values, signatures, credentials, keys, provider secrets, queue payloads, or hidden governance metadata.
- Bounded scans report incomplete coverage visibly.
- Existing PWA `id` remains stable.

## Deferred work

- Authenticated hosted-provider home data.
- Server-enforced permissions and tenant isolation.
- Cross-device live workspace counts.
- Notifications or automatic task delivery.
- AI-generated workspace prioritization.
- Calendar or CRM summary cards.

Any deferred capability requires a separate roadmap issue and must preserve explicit operator authority.
