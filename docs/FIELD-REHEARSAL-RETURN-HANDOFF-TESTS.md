# Field Rehearsal Return Handoff Tests

## Portable integrity core

Run:

```bash
node tests/field-evidence-integrity-core.mjs
```

The integrity suite verifies:

- the helper exposes SHA-256 as a portable computation contract;
- the standard SHA-256 `abc` test vector is reproduced exactly;
- hexadecimal receipts normalize deterministically to lowercase;
- the receipt binds the exact generated bytes, including the trailing newline used by the downloaded JSON payload;
- byte changes produce a different receipt;
- malformed receipts fail validation;
- unavailable Web Crypto fails visibly instead of inventing a digest.

## Portable return core

Run:

```bash
node tests/field-rehearsal-return-core.mjs
```

The return suite verifies:

- all six documented coverage rows can be derived from accepted environment metadata;
- unsupported platform/browser combinations do not acquire a coverage row;
- metadata-incomplete evidence is rejected;
- a valid 64-character SHA-256 receipt is required before a return target can be built;
- launch row drift fails closed;
- launch target-commit drift fails closed;
- matching launch, evidence, and receipt metadata produces a bounded return target;
- return contract `1.1.0` round-trips row, exact commit, readiness, and receipt through deterministic fragment encode/parse logic;
- the normalized selected report is cross-checked against returned row, commit, and readiness;
- row, commit, and readiness drift all fail visibly;
- unknown fragment properties, duplicate fields, and missing receipts are rejected;
- unrelated URL fragments are ignored;
- source evidence and launch objects are not mutated.

## Chromium browser coverage

Run:

```bash
npx playwright test tests/field-rehearsal-return.spec.js --reporter=line
```

The browser suite verifies:

- reviewing evidence alone does not enable the return action;
- explicit metadata download generates a SHA-256 receipt and enables return only when evidence and launch metadata remain valid;
- the returned row, exact commit, readiness, and shortened receipt arrive in `evidence.html`;
- recognized return fragments are removed from the address bar;
- the destination does not auto-populate the file input, read a local file path, or load evidence automatically;
- explicitly selecting the exact downloaded JSON and choosing **Load Selected Evidence** verifies the receipt before accepting the report;
- a still-valid JSON report whose bytes are edited after download is rejected by the returned receipt and leaves coverage evaluation disabled;
- malformed return metadata fails visibly;
- a launched rehearsal whose row is changed before download cannot use the exact-commit return handoff;
- the return layer does not require localStorage or sessionStorage;
- the controls remain contained at a 390px viewport and preserve 44px minimum action height.

## Static boundary checks

The dedicated GitHub Actions workflow checks:

- required static assets and documentation exist;
- JavaScript and test files pass syntax validation;
- both rehearsal and coverage entry points load the integrity core, return core, and browser layer in the required order;
- the service worker pre-caches the integrity and return assets as ordinary static files;
- the explicit download event and explicit receipt-verification event remain present;
- no browser-storage, provider, network, synchronization, transfer-mutation, meeting-mutation, automatic-import, or background-sync implementation is introduced by the receipt/return layer;
- the repository keeps the `hub.methodz.ca` deployment boundary.
