# Methodz Meeting Manager v1.6.21 Release Roadmap

## Release intent

Advance the 1.x evidence roadmap after Field Rehearsal by making large-workspace timing evidence directly comparable through a bounded static workspace.

This release does not claim production performance or real-device readiness. It provides a deterministic comparison surface for metadata reports already generated by the existing Workspace Capacity rehearsal.

## Definition of done

- [x] `performance.html` is reachable from Workspace Home.
- [x] only explicit file loading reads selected JSON evidence.
- [x] portable comparison core accepts only `methodz-workspace-capacity-rehearsal` version `1.0.0` metadata reports.
- [x] source privacy-boundary violations fail closed.
- [x] unknown properties are ignored instead of copied forward.
- [x] imported evidence is bounded to 20 runs and remains in memory only.
- [x] baseline, latest, fastest, median, slowest, target-pass, and regression signals are deterministic.
- [x] comparison summary download is explicit and metadata-only.
- [x] browser storage, provider state, meeting records, queues, and transfer contents are not read.
- [x] service worker caches only the new static application assets.
- [x] portable and Chromium tests cover validation, math, privacy, explicit actions, clearing, and mobile containment.
- [x] app shell remains `1.6.12`.
- [x] meeting-record schema remains `1.6.0`.
- [x] browser-local storage remains the default meeting-record provider.
- [x] no hosted production provider or silent automation is introduced.

## Evidence collection target

Use the existing Workspace Capacity rehearsal to collect comparable reports across:

1. current desktop Chromium baseline;
2. current Firefox or Safari/WebKit desktop baseline;
3. Android phone Chrome;
4. iPhone Safari;
5. tablet browser;
6. later app-shell commits after concrete performance fixes.

Use consistent synthetic record/task counts and target durations when comparing runs. Store screenshots, traces, device details, and other external evidence separately from the metadata comparison summary.

## Next 1.x targets

1. convert concrete regressions or physical-device friction into narrowly scoped GitHub issues;
2. repeat affected field-rehearsal rows after fixes and compare timing evidence again;
3. improve Meeting-Day, Preparation, Follow-Up Planning, Decision Register, and Outcomes only where evidence identifies specific operator friction;
4. keep Calendar, CRM, authentication, and production-provider work inside the explicit 2.0 approval boundary;
5. preserve browser-local storage as the default until a hosted provider satisfies the production evidence gate.
