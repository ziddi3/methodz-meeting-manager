# Methodz Meeting Manager v1.6.10 Changelog

## Added

- Portable application-shell panel registry.
- Stable panel IDs, labels, groups, selectors, insertion anchors, Meeting-Day priorities, default visibility, and print behavior.
- Registration of core capture, saved-record, archive, governance, recovery, provider, synchronization, transfer, acceptance, and diagnostics panels.
- Duplicate-ID, invalid-group, missing-anchor, missing-required-panel, and Meeting-Day order validation.
- Visible fail-safe diagnostics that never hide meeting controls.
- Registry-driven Meeting-Day navigation that no longer depends on visible headings.
- Metadata-only registration and aggregate script-load timing reports.
- Physical-device Android, iOS, tablet, and desktop field-rehearsal runbook.
- Versioned metadata-only field-rehearsal evidence template.
- Node and Playwright panel-registry regression coverage.

## Changed

- App-shell and service-worker cache version advance to `1.6.10`.
- Meeting-record schema remains `1.6.0`.
- Static capture cards now expose stable shell IDs.
- Meeting-Day Mode uses registry selectors and priorities, with heading matching retained only as a compatibility fallback.
- Registry failure blocks supporting-panel collapse and surfaces an explicit repair panel.
- Archive loads the v1.6.10 configuration layer without loading interactive panel-registry behavior.

## Safety boundaries

- No production provider, endpoint, credential, authenticated account, framework, build step, or automatic synchronization is introduced.
- The service worker caches static assets only.
- Registry and field-rehearsal reports exclude meeting content, record IDs, attendee names, signatures, credentials, private-key material, and browser storage values.
- Browser-local registry and field evidence do not authenticate a person or device and do not prove delivery, authority, legal approval, or production durability.
- Methodz Meeting Manager remains a task-focused meeting tool and must not deploy over `hub.methodz.ca`.
