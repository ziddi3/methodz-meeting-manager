# Methodz Meeting Manager v1.6.23 Release Roadmap

## Release intent

Advance the evidence-driven 1.x roadmap by converting one evaluated same-commit Field Evidence Coverage matrix into deterministic, bounded remediation work.

This release does not invent product features from synthetic assumptions. It provides operator tooling for the exact next step already defined by v1.6.22: turn failed, blocked, incomplete, or missing physical-device rows into narrowly scoped work without crossing into automatic issue creation or production infrastructure.

## Definition of done

- [x] remediation logic is isolated in a portable side-effect-free core;
- [x] only `methodz-field-evidence-coverage` and coverage-summary version `1.0.0` inputs are accepted;
- [x] the exact selected commit SHA remains the remediation boundary;
- [x] all six documented rows are required and source privacy boundaries fail closed;
- [x] ready rows are excluded;
- [x] fail maps to code remediation;
- [x] blocked maps to environment remediation;
- [x] incomplete maps to evidence completion;
- [x] missing maps to evidence collection;
- [x] work is bounded to six rows and ordered deterministically;
- [x] blocking issue references remain bounded numeric metadata only;
- [x] building the worklist requires an explicit operator action;
- [x] coverage changes invalidate the derived worklist;
- [x] worklist JSON download is explicit and metadata-only;
- [x] Markdown issue-draft download is explicit;
- [x] the static application makes no GitHub API call and creates no issue automatically;
- [x] browser storage, provider state, meeting records, queues, and transfer contents are not read or written;
- [x] portable and Chromium tests cover validation, ordering, privacy, explicit actions, invalidation, downloads, storage non-use, and mobile containment;
- [x] app shell remains `1.6.12`;
- [x] meeting-record schema remains `1.6.0`;
- [x] browser-local storage remains the default meeting-record provider;
- [x] no hosted production provider or silent automation is introduced.

## Next 1.x targets

1. collect real physical-device evidence for the current application commit;
2. use this worklist only when a real coverage row is fail, blocked, incomplete, or missing;
3. create or update narrowly scoped GitHub issues manually after reviewing the generated draft;
4. after a code remediation, rerun the affected row on the new commit rather than carrying old evidence forward;
5. after an environment-only remediation, rerun the same commit when no code changed;
6. compare Workspace Capacity timing evidence in the same environment when field friction is performance-related;
7. improve Meeting-Day, Preparation, Follow-Up Planning, Decision Register, or Outcomes only where field evidence identifies concrete operator friction;
8. keep Calendar, CRM, authentication, AI summary automation, and production-provider work inside the explicit 2.0 approval boundary;
9. preserve browser-local storage as the default until a hosted provider satisfies the production evidence gate.
