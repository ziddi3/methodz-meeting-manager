# Methodz Meeting Manager v1.6.5 Release Notes

## Offline synchronization rehearsal coordinator

Version 1.6.5 adds a user-controlled synchronization laboratory to the static meeting workspace.

### Added

- Durable browser-local push and pull queue.
- Offline, pending, retryable-error, blocked-conflict, and completed states.
- Tenant-scoped disposable remote storage behind the serialized HTTP-style provider pilot.
- Queue bindings for conflict tokens, idempotency keys, fingerprints, operation, tenant, and record identity.
- Explicit enqueue, preview, process, retry, discard, and conflict-review actions.
- Read-only pull preview.
- Response-loss and uncertain-write reconciliation through idempotent replay.
- Three-way changed-field-path review.
- Explicit Accept Remote, Keep Local, and Rebase & Push decisions.
- Queue recovery after page reload.
- Metadata-only rehearsal reports with integrity checksums.
- Dedicated Node contract tests and GitHub Actions workflow.

### Preserved

- Meeting-record schema `1.6.0`.
- localStorage as the default application provider.
- Plain HTML, CSS, and JavaScript deployment.
- Direct-file and ordinary static-host operation.
- Existing archives, revisions, unknown fields, attachment references, retention, preservation holds, disposition, redaction, approvals, receipts, signatures, public-key custody, and recovery metadata.

### Not introduced

- Production synchronization.
- Firebase, Supabase, Drive, CRM, or Methodz API credentials.
- Authentication tokens.
- Automatic background synchronization.
- Silent conflict resolution.
- Runtime packages, framework, server, or build command.

### Security boundary

The rehearsal report contains operational metadata only. Queue snapshots remain local and are not authenticated remote audit evidence. The hosted-provider contract continues to reject private keys, private JWK parameters, embedded binary payloads, data URLs, and credential-shaped fields.
