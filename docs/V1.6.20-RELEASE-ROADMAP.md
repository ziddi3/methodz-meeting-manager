# Methodz Meeting Manager v1.6.20 Release Roadmap

## Release intent

Advance the post-Workspace-Home 1.x evidence roadmap by making physical-device rehearsal capture an explicit first-class workspace rather than a loose JSON-template exercise.

This release does not claim that physical-device rehearsals have been completed. It supplies the operator surface, evidence contract, and validation needed to perform and preserve those rehearsals consistently.

## Definition of done

- [x] `rehearsal.html` is reachable from Workspace Home.
- [x] portable Field Rehearsal core accepts structured bounded metadata only.
- [x] environment inspection runs only after explicit operator action.
- [x] browser family/version is not inferred from a fingerprinting string.
- [x] readiness is deterministic and only reaches `ready` when all eight required checks pass.
- [x] fail, blocked, not-applicable, and not-run outcomes remain visible.
- [x] generated evidence excludes meeting content, record IDs, attendee names, signatures, storage keys/values, credentials, private keys, provider secrets, queue payloads, transfer contents, and free-form operator notes.
- [x] blocking defects are represented by bounded numeric GitHub issue numbers only.
- [x] evidence download is explicit.
- [x] the service worker caches only the new static assets.
- [x] portable and Chromium tests cover privacy, readiness, explicit actions, and mobile containment.
- [x] app shell remains `1.6.12`.
- [x] meeting-record schema remains `1.6.0`.
- [x] browser-local storage remains the default meeting-record provider.
- [x] no hosted production provider or silent automation is introduced.

## Physical evidence target

After this release lands, use the workspace to complete the real-device matrix:

1. Android phone, current Chrome, HTTPS or localhost;
2. iPhone, current Safari, HTTPS;
3. Android tablet or iPad;
4. desktop Chromium plus Firefox or Safari/WebKit;
5. separate source and destination profiles, preferably on separate physical devices, for transfer, destination acceptance, and rollback.

Every row should use disposable meeting records and protected backups.

## Next 1.x targets

1. collect and compare large-workspace timing evidence through the existing bounded diagnostics;
2. close any physical-device defects with linked GitHub issues and repeat the affected row;
3. improve meeting-day, planning, preparation, and outcomes ergonomics only where field evidence identifies concrete friction;
4. keep Calendar, CRM, authentication, and production-provider work inside the explicit 2.0 approval boundary;
5. preserve browser-local storage as the default until a hosted provider satisfies the production evidence gate.
