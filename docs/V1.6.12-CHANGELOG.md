# v1.6.12 Changelog

## Added

- Explicit Workspace Capacity panel.
- Aggregate browser-local byte and category reporting.
- Optional browser origin usage and quota comparison.
- Bounded, in-memory large-workspace Follow-Up Review rehearsal.
- Metadata-only capacity and performance report download.
- Portable Node tests and Chromium regression coverage.
- Architecture, test, and release documentation.

## Hardened

- No capacity scan runs automatically.
- Capacity collection now enumerates and sorts all key names for deterministic selection and accurate complete entry counts while capping value reads and raw snapshot entries at the configured maximum.
- Any storage length, key-enumeration, selected-value, or consistency-check failure now produces an explicit metadata-safe `unavailable` report and UI state instead of a healthy zero-entry or partial scan.
- Unavailable reports use the fixed `local-storage-read-failed` code, null local scan measurements, and empty categories; raw error objects, messages, and stacks remain excluded.
- Archive matching now precedes active-record matching, so the real overlapping archive storage key is categorized only as **Archive Vault**.
- UTF-8 measurement now reuses a single `TextEncoder` instance.
- Workspace Capacity and Cross-Device Transfer controls no longer trigger meeting-draft autosave, preserving no-write diagnostics and stable transfer-drill fingerprints while leaving meeting capture autosave unchanged.
- Deterministic Node and Playwright regressions cover bounded collection, accurate total and truncation metadata, unavailable read handling, archive precedence, encoder reuse, and privacy boundaries.
- No raw storage keys, values, record IDs, meeting content, credentials, private keys, signatures, queue payloads, or hidden governance details enter reports.
- No synthetic meeting record enters browser storage.
- No automatic cleanup, deletion, archive, compaction, synchronization, or record mutation is available.
- Input sizes, thresholds, and entry scans are bounded.

## Preserved

- Meeting-record schema `1.6.0`.
- Plain HTML, CSS, and JavaScript deployment.
- Direct-file core meeting use.
- Browser-local storage as the default provider.
- Explicit operator control over review, recovery, transfer, synchronization, and destructive actions.
- Static-asset-only service-worker behavior.
