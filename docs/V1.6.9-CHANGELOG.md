# Methodz Meeting Manager v1.6.9 Changelog

## Added

- Guided post-transfer acceptance checklist covering active records, Archive Vault records, revisions, directories, templates, governance metadata, public verification keys, custody records, recovery logs, and tenant queue state.
- Metadata-only acceptance reports with deterministic checksums and bounded local history.
- Operational-evidence filtering so acceptance snapshots exclude drafts, pre-restore packages, transfer reports, acceptance reports, diagnostics reports, accessibility preferences, meeting-day preferences, and rollback-recovery packages.
- Explicit pre-import rollback rehearsal with checksum validation, no-write restore preview, typed approval, current-destination recovery creation, verified restoration, and automatic recovery after failed writes.
- Rollback-preview stability hardening that tolerates only approval-control draft autosave while continuing to invalidate the preview after any substantive workspace change.
- Aggregate large-workspace diagnostics for entry counts, UTF-8 byte estimates, parsing totals, quota ratio, persistence status, scan duration, and bounded warning codes.
- Compact Meeting-Day Mode that keeps the direct capture path visible while collapsing supporting infrastructure panels.
- Sticky phone and tablet section navigation for meeting information, organizations, attendance, agenda, notes, decisions, tasks, summary, and save controls.
- Meeting-day preference and last-section restoration.
- DOM-independent `transfer-acceptance-core.js` for deterministic aggregate reports and tests.
- Two-browser-profile Playwright rehearsal covering transfer, acceptance, diagnostics, rollback, mobile navigation, evidence stability, and metadata exclusion.
- Dedicated GitHub Actions validation for v1.6.9.
- Script-order dependency audit and safe future consolidation plan.

## Changed

- Application-shell version advanced from `1.6.8` to `1.6.9`.
- Static service-worker cache advanced to `methodz-meeting-manager-v1.6.9`.
- `meeting.html` now loads the acceptance core, evidence filter, acceptance workspace, rollback hardening, meeting-day workspace, and v1.6.9 styles.
- `archive.html` now loads the v1.6.9 configuration overlay.
- Acceptance fingerprints remain stable after writing acceptance or diagnostics evidence because those operational entries are excluded from the reviewed workspace snapshot.
- Successful rollback transitions the v1.6.8 transfer state to `rolled-back-to-pre-import`, preventing the restored pre-import workspace from being accepted under stale transfer verification.
- Meeting-Day Mode now preserves every supporting panel's existing hidden state and respects `meetingDay.collapseSecondaryTools`.
- Direct meeting workflows remain first-class while governance and infrastructure tools become collapsible during live meetings.

## Preserved

- Meeting-record schema remains `1.6.0`.
- Browser `localStorage` remains the default provider.
- Direct `file:` operation remains supported for core meeting workflows.
- No framework, package installation, build command, backend, production endpoint, or production credential is required.
- Synchronization, transfer, acceptance, and rollback remain explicit and user-controlled.
- Private signing keys remain excluded from browser storage, workspace packages, transfer bundles, reports, and provider data.
- The service worker remains limited to static assets.

## Safety boundaries

- Acceptance is blocked without a verified v1.6.8 destination import.
- Acceptance is blocked until all required component checks are reviewed.
- Acceptance and diagnostics evidence cannot inflate or invalidate the reviewed workspace fingerprint.
- Rollback is blocked without a valid pre-import package, explicit review, the typed `ROLLBACK` phrase, and final confirmation.
- Substantive destination changes after rollback preview invalidate the preview.
- Draft-only updates caused by the review checkbox or approval phrase are revalidated but do not bypass substantive-change detection.
- Successful rollback invalidates the prior destination-transfer verification.
- Failed rollback read-back restores the original destination snapshot.
- Acceptance, rollback, and diagnostics reports exclude meeting content, names, signatures, raw record IDs, storage-key names, credentials, and private-key material.
- Browser-local evidence does not authenticate a person or device and does not prove delivery, authority, legal approval, or remote audit.
