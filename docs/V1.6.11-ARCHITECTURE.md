# Methodz Meeting Manager v1.6.11 Architecture

## Product boundary

Methodz Meeting Manager remains a task-focused meeting preparation, capture, analysis, archive, recovery, transfer, and records tool. It is not Method Hub, Nexus Hub, a storefront, a business container, the Cathedral, or a Cathedral wing, and it must never deploy over `hub.methodz.ca`.

## Release boundary

```text
Application shell: 1.6.11
Meeting-record schema: 1.6.0
Meeting review core: 1.0.0
Panel registry: 1.0.0
Default provider: browser localStorage
Required backend: none
Required build step: none
```

The shell advances independently from the meeting-record schema. v1.6.11 derives review information from existing records and adds no record fields or migrations.

## Components

### `meeting-review-core.js`

A portable, side-effect-free layer that validates date-only deadlines, classifies saved follow-up tasks, creates a bounded cross-record review, and derives a read-only live meeting pulse across eight capture sections. It never reads browser storage, touches the DOM, or mutates a record.

### `features-v1611-follow-up-review.js`

The browser layer inserts **Meeting Pulse** after quick actions and **Follow-Up Review** after Saved Meeting Records. It navigates through existing Meeting-Day controls, opens a source meeting only after an operator action, exports only after an explicit download action, and stores only the selected review filter.

### Panel registry integration

- `meeting-pulse` is a shell panel with Meeting-Day priority `5`.
- `follow-up-review` is a records panel.
- the nine required capture panels and their order remain unchanged.
- registry failure still leaves meeting and supporting controls visible.

## Script order

1. `config-v1611.js` loads after `config-v1610.js`.
2. `meeting-review-core.js` loads before browser features.
3. historical feature layers create their panels.
4. `features-v1611-follow-up-review.js` creates the review panels.
5. `features-v1610-panel-registry.js` validates and binds the completed shell.
6. `features-v169-meeting-day.js` consumes registry metadata last.

This preserves compatibility globals and avoids a risky feature-layer rewrite.

## Data and security boundaries

- Review rendering does not save or mutate records.
- Follow-up CSV contains visible task and source-meeting fields only.
- Typed signatures, consent records, credentials, private keys, provider secrets, queue payloads, and hidden governance metadata are excluded.
- No production endpoint, authenticated-user claim, background synchronization, automatic delivery, or automatic task update is introduced.
- The service worker caches static files only and never reads meeting or review values.

## Deployment

Core meeting operation remains supported by opening `meeting.html` directly. The repository remains deployable to any ordinary static host. HTTPS or localhost is needed only for optional service-worker and Web Crypto capabilities.
