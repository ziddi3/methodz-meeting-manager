# Methodz Meeting Manager v1.6.8 Changelog

## Added

- Guided Cross-Device Transfer workspace.
- Integrity-checked transfer bundles combining workspace backup, tenant queue, metadata-only operator evidence, and Device Readiness.
- Top-level transfer manifest and checksum.
- Destination collision review for active records, Archive Vault entries, cross active/archive conflicts, revision groups, public verification keys, and queue entries.
- Opaque collision references that do not expose raw identifiers.
- No-write recovery drill and replacement mutation plan.
- Explicit destination confirmations and typed `TRANSFER` approval phrase.
- Complete pre-import recovery package before destination mutation.
- Read-back verification for every imported storage value.
- Automatic restoration of the original destination snapshot when staged mutation or verification fails.
- Bounded metadata-only transfer rehearsal reports.
- Portable Node core tests and Chromium browser tests.
- Dedicated Cross-Device Transfer Rehearsal GitHub Actions workflow.
- v1.6.8 architecture, operator, and test documentation.

## Changed

- App-shell and service-worker cache version advance to `1.6.8`.
- The record schema remains `1.6.0`.
- `meeting.html` loads the v1.6.8 configuration, core, interface, and styling after the v1.6.7 Device Readiness layer.
- `archive.html` loads the current v1.6.8 configuration without loading transfer mutation modules.
- Static validation now includes v1.6.8 assets, wiring, core tests, and service-worker boundaries.
- Project documentation now treats cross-device recovery as an explicit, reversible workflow rather than a checklist alone.

## Safety notes

- Transfer bundles contain business and meeting data and must be protected like complete workspace backups.
- Transfer reports are metadata-only and exclude meeting values, raw record IDs, names, signatures, credentials, and private keys.
- Workspace, queue, operator-evidence, readiness, and top-level integrity checks must all pass.
- Import is previewed and drilled before mutation.
- Revalidation occurs immediately before mutation.
- Private JWK material, private-key fields, credentials, and rejected embedded binary payloads fail closed.
- Queue entries remain unprocessed after import.
- The service worker continues to cache static assets only.
- No backend, production endpoint, credential, framework, build command, runtime dependency, automatic synchronization, or silent conflict resolution is introduced.
- Browser-local evidence does not authenticate a person or device and does not prove authority, delivery, approval legitimacy, or legal compliance.
