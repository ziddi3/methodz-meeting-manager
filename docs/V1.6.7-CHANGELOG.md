# Methodz Meeting Manager v1.6.7 Changelog

## Added

- Metadata-only Device Readiness workspace.
- Browser storage write probe, quota estimate, persistence status, service-worker/direct-file status, Web Crypto state, connection state, viewport-fit check, and aggregate workspace counts.
- Explicit persistent-storage request.
- Downloadable readiness report that excludes meeting content, record IDs, attendee names, signatures, credentials, and cryptographic key material.
- Cross-device transfer checklist with clipboard and download fallback.
- Phone action dock for Save, New, Records, and Device.
- 44-pixel touch targets, 16-pixel mobile form controls, safe-area support, single-column narrow layouts, and page-level horizontal-overflow protection.
- Device Readiness application shortcut.
- Dedicated Mobile Readiness GitHub Actions workflow and phone-viewport Playwright suite.
- v1.6.7 architecture and manual test documentation.

## Changed

- App-shell and service-worker cache version advance to `1.6.7`.
- Meeting-record schema remains `1.6.0`.
- Main and archive entry points load `config-v167.js` and `features-v167.css`.
- The main meeting workspace loads `features-v167-device-readiness.js` after the v1.6.6 synchronization portability feature.
- Static, provider, pilot, synchronization, recovery, custody, and browser checks recognize the current shell while retaining version-specific v1.6.6 assertions.
- The workspace introduction now foregrounds meeting preparation, capture, assignment, summary, archive, and safe transfer.

## Preserved from v1.6.6

- Tenant-scoped synchronization rehearsal queues.
- Integrity-checked queue export and import.
- No-write queue import preview and explicit approval.
- Keep-local, newest-metadata, and retain-both merge strategies.
- Protected completed-entry compaction.
- Reload recovery and metadata-only operator evidence.
- Rejection of private keys, credentials, embedded binary payloads, tampering, unsupported package versions, and cross-tenant imports.
- No background or service-worker queue processing.

## Security and privacy notes

- Readiness reports do not include queue contents or workspace values.
- Persistent storage is requested only through explicit user action.
- Device readiness does not prove that a backup exists or that recovery will succeed.
- No production endpoint, credential, backend, framework, runtime dependency, build step, schema migration, or automatic synchronization is introduced.
- Browser-local `localStorage` remains the default provider.
