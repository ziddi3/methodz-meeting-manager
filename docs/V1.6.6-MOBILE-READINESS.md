# Methodz Meeting Manager v1.6.6 Mobile and Cross-Device Readiness

## Product purpose

Methodz Meeting Manager remains a task-focused meeting preparation, capture, analysis, archive, and records tool. The v1.6.6 layer makes that direct workflow safer and easier to use on phones, tablets, installed PWAs, browser tabs, and direct-file deployments.

This release does not convert the application into Method Hub, Nexus Hub, a business storefront, the Cathedral, or a hosted synchronization service.

## Release identity

- App shell: `1.6.6`
- Meeting-record schema: `1.6.0`
- Default record provider: browser-local `localStorage`
- Runtime framework: none
- Build command: none
- Required server: none
- Production synchronization endpoint: none

## Device Readiness panel

`features-v166-device-readiness.js` creates a user-facing Device Readiness panel after the meeting quick actions. It checks:

- browser storage write access;
- browser-provided storage usage and quota estimates;
- persistent-storage status;
- service-worker control or direct-file mode;
- Web Crypto availability;
- current online/offline state;
- page-level viewport fit;
- counts of active records, archived records, revision groups, drafts, templates, directories, and queued synchronization rehearsals.

The overall state is one of:

- **Ready**: no current capability warning was detected;
- **Review**: the workflow remains usable but one or more conditions deserve attention;
- **Limited**: browser storage is unavailable and the offline workspace cannot safely save records.

These states are operational hints, not guarantees.

## Metadata-only report boundary

The downloadable readiness report includes capability and count metadata only. It intentionally excludes:

- meeting titles and notes;
- decisions and tasks;
- attendee and organization names;
- record identifiers;
- typed signatures;
- credentials and access tokens;
- private or public key material;
- workspace storage values.

A readiness report does not prove that a protected backup exists, that a restore will succeed, or that a destination device is authorized.

## Persistent storage

The app never requests persistent browser storage automatically. The request remains an explicit user action.

A granted persistence request may reduce browser eviction risk. It does not replace:

- a complete workspace backup;
- protected off-device storage;
- a no-write package inspection;
- a recovery rehearsal;
- independent verification of important records and public-key IDs.

## Mobile action dock

At phone widths, the app displays a fixed four-action dock:

- Save
- New
- Records
- Device

The dock calls existing stable meeting functions rather than creating a second record workflow. It is hidden when printing.

## Mobile layout hardening

`features-v166.css` adds:

- 44-pixel minimum touch targets;
- 16-pixel mobile form controls to reduce browser input zoom;
- safe-area padding for notched devices;
- narrow-screen single-column grids;
- bounded cards, code blocks, and record panels;
- mobile quick-action and button layouts;
- page-level horizontal-overflow protection;
- print exclusions for device-only controls.

## Cross-device transfer sequence

1. Save the current meeting and confirm it appears in Saved Meeting Records.
2. Export a complete Workspace Backup.
3. Store the backup outside the browser and source device.
4. Keep private signing keys separate from workspace backups and signed packages.
5. Run Device Readiness on the destination browser.
6. Inspect the backup and run a no-write recovery drill.
7. Apply the restore only after the package and mutation plan are understood.
8. Confirm active, archived, revision, directory, template, governance, and receipt counts.
9. Keep the source workspace unchanged until destination verification is complete.
10. Export a fresh backup after the transfer.

## Deployment behavior

The v1.6.6 files are ordinary static assets. The core meeting workflow still works when `meeting.html` is opened directly. HTTPS or localhost is recommended for service-worker and Web Crypto availability.

The service worker caches the new configuration, style, and readiness feature files under `methodz-meeting-manager-v1.6.6`.

## Security and privacy limits

Device capability checks do not provide authentication, authorization, identity proof, delivery proof, legal approval, durable audit, or remote backup. Browser-reported storage estimates and network state may be incomplete or change after the report is generated.
