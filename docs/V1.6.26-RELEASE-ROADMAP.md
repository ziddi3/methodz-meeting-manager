# Methodz Meeting Manager v1.6.26 Release Roadmap

## Release intent

Advance the evidence-driven 1.x roadmap by closing the return path from a completed physical-device Field Rehearsal back to the exact-commit Coverage Matrix.

This release does not transfer evidence automatically. It preserves the operator-controlled file boundary while carrying enough bounded metadata to prevent row and commit context from being lost between the rehearsal and coverage workspaces.

## Definition of done

- [x] return logic is isolated in a portable side-effect-free core;
- [x] the return core recognizes only the six documented coverage rows;
- [x] a return target is derived only from metadata-complete Field Rehearsal evidence;
- [x] when launch metadata exists, row drift or target-commit drift fails closed;
- [x] the return action remains disabled until the operator explicitly downloads the evidence report;
- [x] only contract version, row key, exact commit SHA, and readiness cross the handoff;
- [x] the report file, report contents, file path, meeting data, credentials, provider state, queues, and arbitrary notes do not cross the handoff;
- [x] recognized return fragments are validated and removed from the Coverage Matrix address bar;
- [x] the destination shows exact row/commit guidance while file selection and loading remain explicit;
- [x] malformed or tampered return metadata fails visibly;
- [x] no browser storage, provider, GitHub API, synchronization, transfer mutation, automatic evidence import, or background automation is introduced;
- [x] portable and Chromium tests cover row derivation, launch drift, explicit download gating, return-fragment validation, destination guidance, storage non-use, and mobile containment;
- [x] app shell remains `1.6.12`;
- [x] meeting-record schema remains `1.6.0`;
- [x] browser-local storage remains the default meeting-record provider;
- [x] no hosted production provider or deployment over `hub.methodz.ca` is introduced.

## Next 1.x targets

1. use the launch and return handoffs on real Android, iOS, tablet, desktop Chromium, desktop non-Chromium, and two-device rehearsals for the current target commit;
2. explicitly load each downloaded report into the Coverage Matrix and verify that the expected row appears under the exact commit tested;
3. when a row fails, keep remediation limited to the smallest evidence-supported code cause;
4. after code remediation, enter the actual resulting commit SHA and rerun all six rows because the evidence boundary changed;
5. after environment-only or evidence-only work, rerun only unresolved rows while the code commit remains unchanged;
6. compare Workspace Capacity timing evidence when field friction is performance-related;
7. improve Meeting-Day, Preparation, Follow-Up Planning, Decision Register, or Outcomes only when real field evidence identifies operator friction;
8. keep Calendar, CRM, authentication, AI summary automation, and production-provider work inside the explicit 2.0 approval boundary;
9. preserve browser-local meeting storage as the default until a hosted provider satisfies the production evidence gate.
