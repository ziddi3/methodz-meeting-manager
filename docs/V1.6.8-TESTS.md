# Methodz Meeting Manager v1.6.8 Test Plan

## Automated core checks

Run:

```bash
node tests/v168-transfer-rehearsal.mjs
```

The core suite verifies:

- workspace, queue, operator-evidence, readiness, and top-level checksums;
- metadata-only readiness boundaries;
- active, archived, revision, public-key, and queue collision review;
- opaque collision references;
- metadata-only rehearsal reports;
- transfer-package tamper rejection;
- private JWK rejection;
- unsafe readiness-report rejection.

## Automated browser checks

Run the static server:

```bash
python3 -m http.server 4173 --bind 127.0.0.1
```

Then run:

```bash
npx playwright test tests/v168-transfer-rehearsal.spec.js --reporter=line
```

The browser suite verifies:

- the transfer panel loads in the static app;
- transfer packages are inspected before mutation;
- the recovery drill is no-write;
- final import requires all confirmations, the `TRANSFER` phrase, and a confirmation dialog;
- a pre-import recovery package is created;
- imported values are verified after mutation;
- metadata reports exclude meeting content and raw record IDs;
- tampered packages fail closed;
- narrow phone viewports avoid page-level horizontal overflow.

## Manual two-device rehearsal

Use disposable browser profiles and non-production sample records.

### Source

- [ ] Save a sample meeting.
- [ ] Add one Archive Vault record.
- [ ] Add revision history.
- [ ] Add one public verification key containing public material only.
- [ ] Add pending synchronization rehearsal work.
- [ ] Run Device Readiness.
- [ ] Build and download a transfer bundle.
- [ ] Confirm the source workspace remains unchanged.

### Destination

- [ ] Open a separate browser profile or device.
- [ ] Run Device Readiness.
- [ ] Seed one disposable collision if collision coverage is required.
- [ ] Choose the transfer bundle.
- [ ] Confirm all component integrity checks pass.
- [ ] Review collision counts.
- [ ] Run the no-write recovery drill.
- [ ] Confirm destination storage is unchanged after the drill.
- [ ] Complete the destination confirmations.
- [ ] Type `TRANSFER`.
- [ ] Approve the final confirmation.
- [ ] Confirm a pre-import recovery package exists.
- [ ] Reload the destination.
- [ ] Verify active records, Archive Vault records, revisions, directories, templates, governance data, public keys, custody data, recovery logs, and tenant queue entries.
- [ ] Confirm no queue entry processed automatically.
- [ ] Download the metadata-only report and inspect it for content leakage.
- [ ] Export a fresh destination workspace backup.

## Rollback rehearsal
