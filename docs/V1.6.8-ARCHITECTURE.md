# Methodz Meeting Manager v1.6.8 Architecture

## Release boundary

Version 1.6.8 adds a cross-device transfer rehearsal layer without changing the record schema, default provider, deployment model, or service-worker responsibilities.

```text
App shell:     1.6.8
Record schema: 1.6.0
Runtime:       Static HTML, CSS, JavaScript
Default store: Browser localStorage
Backend:       None
Build step:    None
```

## Modules

### `config-v168.js`

Declares the app-shell version, transfer storage keys, approval phrase, integrity requirements, report cap, and production boundaries.

### `cross-device-transfer-core.js`

Portable browser/Node logic that:

- validates workspace packages through `workspace-package-core.js`;
- validates tenant queue and operator-evidence packages through `sync-queue-portability.js`;
- validates metadata-only Device Readiness reports;
- builds and verifies the top-level transfer package;
- calculates opaque destination collision references;
- produces metadata-only rehearsal reports.

The core contains no DOM or localStorage mutation logic.

### `features-v168-transfer-rehearsal.js`

Browser orchestration that:

- gathers existing workspace, queue, evidence, and readiness components;
- downloads the source bundle;
- previews destination packages before mutation;
- runs a no-write replacement-plan drill;
- enforces explicit checkboxes, approval phrase, and final confirmation;
- creates a complete pre-import recovery package;
- stages recognized localStorage replacement;
- verifies each written value;
- restores the prior snapshot if writing or verification fails;
- persists bounded metadata-only reports.

### `features-v168.css`

Responsive presentation for source, destination, collision, drill, and approval stages. The interface is hidden from print output.

## Package composition

```text
methodz-cross-device-transfer-rehearsal
├── workspace package
│   ├── meeting records
│   ├── Archive Vault
│   ├── revisions
│   ├── directories and templates
│   ├── governance and receipts
│   ├── public-key and custody metadata
│   ├── recovery logs
│   └── recognized Methodz storage entries
├── tenant synchronization queue package
├── metadata-only operator-evidence package
├── metadata-only Device Readiness report
├── component manifest
├── operator checkpoints
├── explicit boundary declarations
└── top-level integrity checksum
```

The transfer package contains business data. The rehearsal report does not.

## Validation order

Destination inspection is fail closed:

1. Validate top-level package type, version, timestamp, and opaque source reference.
2. Verify top-level integrity.
3. Inspect and checksum-verify the workspace package.
4. Inspect and checksum-verify the tenant queue package.
5. Inspect and checksum-verify operator evidence.
6. Verify Device Readiness metadata-only boundary declarations.
7. Compare manifest integrity declarations.
8. Calculate destination collisions.
9. Generate a no-write restore plan.
10. Re-run the complete inspection immediately before mutation.

No destination mutation is allowed when any required integrity result is absent or false.

## Collision architecture

Collision review operates on identifiers but returns only opaque FNV-1a references. Categories are:

- active versus active;
- archive versus archive;
- incoming active versus local archive;
- incoming archive versus local active;
- revision group;
- public verification key;
- synchronization queue entry.

Collision review does not merge or resolve records. It informs the operator before an explicit destination replacement.

## Transaction and rollback

Before mutation, the browser creates a complete current-workspace package and stores it as the pre-import recovery package.

The transaction then:

1. Preserves v1.6.8 control-state, report, and recovery keys.
2. Removes other recognized destination Methodz keys.
3. Writes verified incoming entries.
4. Reads each written entry back and compares it with the inspected value.
5. Restores the original destination snapshot if any step throws or verification differs.

This is a browser-local compensation transaction, not a database transaction. The explicit recovery package remains the durable rollback path.

## Evidence separation

### Transfer bundle

Contains meeting and workspace values. It must be protected like a complete business backup.

### Rehearsal report

Contains only:

- opaque session references;
- integrity booleans;
- aggregate record, archive, revision, queue, event, and collision counts;
- checkpoint booleans;
- recovery, mutation, rollback, and verification outcomes;
- app-shell and schema versions;
- timestamp and checksum.

It excludes raw identifiers, titles, notes, attendees, signatures, credentials, key material, queue payloads, and record values.

## Private-material boundary

Existing provider and workspace validators reject private JWK parameters, private-key fields, credential fields, embedded binary values, and data URLs before a transfer package is created or imported.

Public verification keys remain allowed because they are required for portable signature verification and contain no private JWK parameter.

## Service-worker boundary

`service-worker.js` caches the v1.6.8 static shell. It has no Background Sync handler and no code that reads or processes:

- localStorage;
- meeting records;
- workspace packages;
- transfer packages;
- rehearsal reports;
- queue entries;
- private keys.

## Compatibility

- Core meeting workflows remain usable through `file:` URLs.
- Transfer downloads and imports use ordinary browser file controls.
- Hosted offline caching still requires HTTPS or localhost.
- The feature introduces no runtime package dependency.
- Playwright remains CI-only.
- Earlier package and record formats remain unchanged.
